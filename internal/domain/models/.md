## 1. Roles

Роли: `admin`, `experimenter`, `approver`, `viewer`.

```text
GET    /roles
GET    /roles/:id

POST   /roles
PUT    /roles/:id
DELETE /roles/:id
```

### Примеры

```http
GET /roles
```

```http
GET /roles/:id
```

```http
POST /roles
```

```json
{
  "name": "experimenter"
}
```

# 3. Feature Flags

Основные endpoints:

```text
POST   /feature-flags
GET    /feature-flags
GET    /feature-flags/:id
PUT    /feature-flags/:id
DELETE /feature-flags/:id
```

Но здесь есть важное ограничение из ТЗ:

> После создания Feature Flag можно менять только `defaultValue`.

Поэтому я рекомендую сделать отдельный endpoint:

```text
PATCH /feature-flags/:id/default
```

### Создание

```http
POST /feature-flags
```

```json
{
  "key": "button_color",
  "valueType": "string",
  "defaultValue": "green"
}
```

Другой пример:

```json
{
  "key": "new_checkout",
  "valueType": "bool",
  "defaultValue": "false"
}
```

### Изменение default value

```http
PATCH /feature-flags/:id/default
```

```json
{
  "value": "blue"
}
```

`key` и `valueType` после создания не меняем.

# 4. Experiments

Основные:

```text
POST   /experiments
GET    /experiments
GET    /experiments/:id
PUT    /experiments/:id
DELETE /experiments/:id
```

Lifecycle:

```text
POST /experiments/:id/transition
```

Например:

```json
{
  "status": "review"
}
```

Review:

```text
POST /experiments/:id/approve
POST /experiments/:id/request-changes
POST /experiments/:id/reject
GET  /experiments/:id/approvals
```

Versions:

```text
GET /experiments/:id/versions
GET /experiments/:id/versions/:version
```

Завершение:

```text
POST /experiments/:id/complete
```

### Создание Experiment

```http
POST /experiments
```

```json
{
  "featureFlagId": "uuid",
  "name": "Button Color Experiment",
  "audiencePercent": 20,
  "variants": [
    {
      "name": "blue",
      "value": "blue",
      "weight": 10,
      "isControl": true
    },
    {
      "name": "red",
      "value": "red",
      "weight": 10,
      "isControl": false
    }
  ]
}
```

Здесь сервис должен проверить:

```text
audiencePercent = 20

10 + 10 = 20  ✅

control variants = 1  ✅
```

# 5. Variants

Variants принадлежат Experiment, поэтому URL делаем вложенным:

```text
POST   /experiments/:id/variants
GET    /experiments/:id/variants
GET    /experiments/:id/variants/:variantId
PUT    /experiments/:id/variants/:variantId
DELETE /experiments/:id/variants/:variantId
```

### Создание Variant

```http
POST /experiments/:id/variants
```

```json
{
  "name": "blue",
  "value": "blue",
  "weight": 10,
  "isControl": true
}
```

### Обновление

```http
PUT /experiments/:id/variants/:variantId
```

```json
{
  "name": "red",
  "value": "red",
  "weight": 10,
  "isControl": false
}
```

Но сервис должен проверить, что эксперимент позволяет это изменение. Например, если Experiment уже `running`, менять allocation-параметры нельзя.

# Общая структура

В итоге первые 5 модулей выглядят так:

```text
/roles
    GET    /
    GET    /:id
    POST   /
    PUT    /:id
    DELETE /:id

/users
    POST   /
    GET    /
    GET    /:id
    PUT    /:id
    DELETE /:id

/feature-flags
    POST   /
    GET    /
    GET    /:id
    PUT    /:id
    DELETE /:id
    PATCH  /:id/default

/experiments
    POST   /
    GET    /
    GET    /:id
    PUT    /:id
    DELETE /:id

    POST   /:id/transition
    POST   /:id/approve
    POST   /:id/request-changes
    POST   /:id/reject
    GET    /:id/approvals

    GET    /:id/versions
    GET    /:id/versions/:version
    POST   /:id/complete

/experiments/:id/variants
    POST   /
    GET    /
    GET    /:variantId
    PUT    /:variantId
    DELETE /:variantId
```

### Но есть один архитектурный момент

Я бы **не делал `DELETE /experiments/:id` и `DELETE /feature-flags/:id` бездумно**.

У тебя есть lifecycle и audit. Поэтому для Experiment правильнее:

```text
completed → archived
```

а не просто удалить запись из БД.

И для Feature Flag нужно учитывать, что на него могут ссылаться Experiments.

**Следующий шаг:** можно теперь сделать для этих 5 сущностей **точные Request/Response DTO** — какие поля принимает каждый endpoint и что возвращает. Это уже будет практически готовый контракт для frontend и Swagger.
