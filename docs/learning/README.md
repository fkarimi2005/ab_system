# Учебные материалы по проекту

Эти файлы объясняют, **как и почему** реализованы шаги, которые были написаны вместе с ассистентом. Цель: чтобы вы могли пересказать и защитить каждое решение.

Читайте по порядку: каждый следующий файл опирается на предыдущие.

| Файл | О чём |
|---|---|
| [00-architecture.md](00-architecture.md) | слои, путь запроса, ошибки, логи, база: общая основа |
| [01-catalogs.md](01-catalogs.md) | шаг 1: каталоги событий и метрик, метрики и guardrails в эксперименте |
| [02-targeting.md](02-targeting.md) | шаг 2: правила таргетинга (DSL) |
| [03-decide.md](03-decide.md) | шаг 3: Decide API, корзины, варианты, `decision_id` |
| [04-events.md](04-events.md) | шаг 4: приём событий, дедупликация, атрибуция |

## Как учить
1. Прочитайте файл, затем откройте указанные в нём файлы кода и найдите те же места.
2. Ответьте на «Вопросы для самопроверки» **вслух, не заглядывая**.
3. Повторите живой сценарий из раздела «Как показать проверяющему» на своей машине.
4. Попробуйте сломать: измените правило в коде (например, уберите `AND status = from`) и посмотрите, какой тест или сценарий это заметит.

## Что должны уметь объяснить на защите
- Почему слои именно такие и где живёт каждое правило.
- Как обеспечены детерминизм и stickiness в Decide.
- Как работает дедупликация и почему атрибуция считается при чтении.
- Какие упрощения мы сделали и почему они приемлемы (раздел «Известные упрощения» в каждом файле).
